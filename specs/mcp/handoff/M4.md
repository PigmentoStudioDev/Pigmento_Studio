# M4 — La key en la URL, para Claude web
Fecha: 2026-09-21 · Agentes: sesión principal + `security-reviewer`

**Por qué.** Karen quiere enseñarle la feature a un cliente desde claude.ai. Un conector
personalizado de ahí solo acepta una URL (y OAuth opcional): no manda headers, y el plugin
autentica por `Authorization`. OAuth de verdad —el camino de Atom, con su propio servidor
de autorización— es mucho peso para una demo de una persona, así que se toma el camino
corto y se escribe su precio.

## DoD

- [x] **`overrideAuth` pasa la key de la query al resolvedor por defecto del plugin.** No
      es un segundo camino de auth: `getDefaultMcpAccessSettings(apiKey?)` es la MISMA
      función que corre en cada petición, y su argumento opcional existe para esto.
- [x] **Test primero**: cinco casos en rojo antes del código (`apiKeyFromUrl` no existía).
- [x] **Verificado en vivo** contra `pnpm dev`, con `tools/list`:

      | petición | respuesta |
      | --- | --- |
      | sin nada | 401 |
      | `?key=` correcta | 200, 25 tools |
      | `?key=` falsa | 401 |
      | header `Bearer` correcto (como antes) | 200 |
      | header correcto + `?key=` falsa | 401 (manda la query) |

- [x] `security-reviewer`: **APPROVE, critical=0 high=0**, sin cambios pedidos. Verificó
      que la query conserva índice HMAC, búsqueda en base, binding de usuario y toggles por
      key; que `URLSearchParams.get` no puede devolver un array; que una key vacía o una URL
      malformada caen al header; y que ni este repo ni el plugin escriben la URL en un log.
- [x] `./scripts/gates.sh` verde — 0 fallos, 0 avisos, **960 tests**.

## Decisiones dentro del alcance
- **La query manda sobre el header.** Es lo que sale de pasar la key al resolvedor sin
  condicionarla. El peor caso es un falso negativo (header bueno + query vieja → 401), que
  es molestia, no agujero: las dos ramas acaban en la misma verificación contra la base.
- **No se añade `Cache-Control: no-store`.** El transporte es POST y ninguna caché guarda
  un POST por defecto; el riesgo real son los logs de plataforma, y contra eso lo que sirve
  es una key aparte y revocable, que es la mitigación escrita.
