## Q2 — `buildConfig` sin `editor`

**Respuesta.** `buildConfig` **no exige** `editor` si no hay campos `richText`. `payload generate:types` sobre un config minimo (secret + sqlite + una coleccion `text`, sin `editor`) termino 0 y escribio `payload-types.ts`. En ese archivo no aparecen `lexical`, `editor` ni `richText`.

En tipos de 3.88.0, `editor` es opcional (`editor?: RichTextAdapterProvider`). `sanitize.js` solo invoca el editor `if (typeof incomingConfig.editor === 'function')`. En la tabla de opciones del config, los requeridos con asterisco son `db` y `secret`, no `editor`.

**Fuente (comando).** Config usado (`/tmp/payload-s0-q2/payload.config.ts`):

```ts
export default buildConfig({
  secret: 's0-audit-not-a-real-secret-xxxxxxxxxxxxxxxx',
  db: sqliteAdapter({
    client: { url: 'file:./scratch.db' },
  }),
  collections: [
    { slug: 'notes', fields: [{ name: 'title', type: 'text' }] },
  ],
  typescript: { outputFile: path.resolve(dirname, 'payload-types.ts') },
})
```

## Q3 — `@payloadcms/storage-r2` es de Workers

**Respuesta.** `@payloadcms/storage-r2@3.88.0` es el adaptador nativo de **Cloudflare Workers** (binding `R2Bucket`). No es el cliente S3. En Node sobre Vercel no sustituye a `@payloadcms/storage-s3`. La doc oficial: R2 desde Vercel/Netlify/Node va por la API S3-compatible con `storage-s3`; `storage-r2` es «for Cloudflare Workers only».

El paquete publicado no trae README (`readme = ''`). El source pide `bucket: R2Bucket`, no `endpoint`/`accessKeyId`.
