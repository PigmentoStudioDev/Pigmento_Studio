`claude plugin install cloudflare@cloudflare`) da 14 skills y el MCP de la API.

| `R2_ENDPOINT` | `https://c6e2436643dc1d374299a5d2645a98e8.r2.cloudflarestorage.com` |
| `R2_PUBLIC_URL` | `https://pub-689bd7bf1ef94ab08b150945eac861e5.r2.dev` |

**El OAuth del MCP NO puede crear tokens** (`9109 Unauthorized` en `/accounts/{id}/tokens`
y en `/user/tokens/permission_groups`). La doc dice que la API lo permite, pero con una
API key con permisos de token, no con este grant. Lo creo Karen en el dashboard.

Del token de cuenta que dio: **Access Key ID = su `id`** y **Secret Access Key =
SHA-256 de su `value`**. Verificado con un `ListObjectsV2` real contra el bucket.

Para obtener el `id` hay que pegarle a `/accounts/{id}/tokens/verify`: el endpoint de
USUARIO devuelve `Invalid API Token` cuando el token es de cuenta, que es justo lo que
despista. Los valores viven en `.env` y no se escriben aqui — ni siquiera el Access Key
ID, que sin ser el secreto identifica una credencial viva.

## Cuatro cosas que se decidieron aqui

1. **`push: false` tambien en local** — corrige `01-decisiones.md` §1. Ver el motivo alli.
2. **`prefix: 'pigmento/media'`.** El bucket `freelance` NO es solo nuestro: ya sirve el
   video del hero y assets de otros proyectos. La primera prueba subio `01.png` a la RAIZ,
   donde puede pisar el `01.png` de cualquier otro sin aviso. Se borro y se resubio bajo
   el prefijo.
3. **`enabled` exige el bucket Y las dos claves.** Colgarlo solo de `R2_BUCKET` encendia
   el plugin a medias, y cada subida moria en un error de firma de S3 que no menciona la
   configuracion.
4. **`generateFileURL` y `remotePatterns` tipados de verdad**, sin `any`: el contrato de
   React lo prohibe. `remotePatterns` estrecha el esquema COMPROBANDO (`!== 'http' &&
   !== 'https'` devuelve `[]`), no afirmando con un cast: una `R2_PUBLIC_URL` con otro
   esquema tiene que quedarse fuera.
